### DIVERGENCE-1: `contracts/solidity/LiquidityOcean.sol` — formula split (MINOR, JUSTIFIED)

- **File:** `contracts/solidity/LiquidityOcean.sol:75-93` (`_recomputeOcean()` function)
- **What diverges:** Solidity computes `ocean_score = Σ(NL_k × W_k) / Σ W_k` (cross-chain NL-weighted average across integrated chains). Canon §17 specifies `LIQUIDITY_OCEAN_SCORE(asset, chain, t) = Σ_forms [VALUE(form_k) × 1/SHIFT_COST × 1/SHIFT_TIME × BEHAVIORAL_HEALTH(holder)]` (per-asset, form-equivalent sum).
- **Canon citation:** C2 §6.1 (form-equivalent liquidity tracking) + §17 LIQUIDITY_OCEAN_SCORE formula.
- **Why justified:** The verbatim §17 form-equivalent formula requires `akashic.get_equivalent_forms(asset)` enumeration (aUSDC, cUSDC, LP positions, etc.) — an off-chain Akashic Index operation that cannot run on-chain within gas limits. The canon-correct formula IS implemented in `anima-service/liquidity_ocean.py` (verified in §1.3 row 2 above with `tests/unit/trion_protocol/test_liquidity_ocean.py::test_total_score_is_the_spec_sum`). The Solidity contract serves a different on-chain purpose: real-time cross-chain NL aggregation for routing threshold checks (`getBestChain()` at L97 returns chain with highest NL×weight). This is a justified layer split — on-chain thin aggregator + off-chain full form-equivalent score.
- **Fix-or-justify recommendation:** **JUSTIFIED — no change required.** Optionally rename to `LiquidityOceanAggregator.sol` for naming clarity, or add a `getFormEquivalentScore()` view that reads pre-computed values from a relayer-updated mapping. The off-chain Python implementation is canon-correct and tested.
