# Deep Read Supplement: PR #4 — `contracts/cairo/` (13 Cairo 2.x contracts)

**Agent:** main-agent · **Scope:** all 22 files merged in commit 7d68e56 / merge 59d9cd0 (`feat: add Cairo 2.x contracts for Starknet deployment`), read in full (~1,755 lines Cairo + configs + README + `chains/svm/Cargo.toml` change).

## Overview

PR #4 adds a **third generation of Cairo contracts** to the repo. Per report 02, `chains/starknet/` already contained two coexisting Cairo generations (minimal no-auth `contracts/*.cairo` + a solid evented `src/cairo/*.cairo` suite). `contracts/cairo/` is a new top-level port of the EVM Solidity contract set — structurally clean Cairo 2.x (Scarb, starknet 2.8.4, edition 2023_11, proper `#[starknet::contract]` / storage / events / interfaces) — but the ports are **simplified skeletons that drop most of the security substance of their EVM counterparts**, and two of them hardcode their "proofs."

## Cross-cutting observations

1. **The theater pattern repeats at contract level.** The EVM tier's genuinely hardened features — ECDSA quorum publishing, BEO binding, 300s verdict expiry, sweep protection — exist as *names* in the Cairo ports but not as *mechanisms*: quorum is a stored-but-unchecked number; the BEO gate is an owner-set cache; routes never expire; the firewall always approves; the attack "proofs" are hardcoded `true`.
2. **Oracle addresses are stored as props.** Five contracts (`TRIONFirewall`, `TRIONLiquidityGuard`, `TRIONProtectedVault`, `AttackSimulator`, `ConfidentialCoherenceVault`) store an oracle address and never call it — the address functions as set dressing.
3. **Third-generation Cairo duplication.** With `chains/starknet/contracts/`, `chains/starknet/src/cairo/`, and now `contracts/cairo/`, the repo contains **three coexisting Cairo codebases** implementing overlapping contracts (three TRIONOracles, two sensing oracles, two execution gates) — extending the repo-wide duplicate-module problem (report 01, §"Conflicting duplicate modules") into a third language tier.
4. **Licensing inconsistency continues**: MIT Scarb.toml vs CC0 headers on two files vs repo-root CC0 vs package.json MIT (report 09).
5. **No tests** in the Cairo crate (no `#[test]` modules, no Scarb test scripts, no CI workflow addition for Cairo) — the README's deployment-order narrative is untestable as committed. `ci-solidity.yml` was not extended to cover Cairo/Scarb.

## Verdict

`contracts/cairo/` is a structurally idiomatic Cairo 2.x skeleton set whose individual contracts are readable and evented — but as security infrastructure it is a **degraded port**: the two contracts that carry the repo's flagship claims (`AttackSimulator`, `AkashicProof`) record hardcoded or unverified assertions, and the two that carry value risk (`ConfidentialCoherenceVault`, `TRIONProtectedVault`) neither custody tokens nor consult the oracle. The Sensing Oracle port is the only one approaching production quality. Recommended priorities: make the oracle calls real (or delete the stored-unused oracle addresses), add a quorum check to `publish_btcp_route`, port the 300s expiry, back `coherence_wrap` with actual token custody, remove the hardcoded attack-proof constants, include `mod interfaces;` or delete the dead directory, and add at least one Scarb test module.
