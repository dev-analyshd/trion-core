# Deep Read: chains/ + trion-0g/ (agent 2-b)

**Scope:** 100 files — 89 under `chains/` (starknet 30, pvm 24, ton 13, near 8, svm 7, sui 3, botchain 3, shared 1) + 11 under `trion-0g/`. Every source file read in full; 11 lockfiles (9 npm `package-lock.json`, `Cargo.lock` ×2 near, `Cargo.lock` pvm-contracts, `Cargo.lock` svm, `Scarb.lock`) characterized by header/size only (see inventory). ~12,600 lines of source excluding locks.

---

## Overview

`chains/` is **not** an "indexer per chain" package — it is a collection of per-chain **"behavioral executors"** (TypeScript scripts that each fire 5 self-transfers of dust on mainnet, or fall back to string "block proofs", then POST a 128-dim vector to the FAISS service at `/index/add_batch`) plus per-chain **smart-contract suites** (Cairo for StarkNet, ink! for Polkadot, FunC for TON, near-sdk Rust for NEAR, a Python block-entropy indexer for Solana, a bare executor for Sui, and an EVM executor for BOT Chain). `trion-0g/` is a small Node SDK integrating 0G Galileo **testnet** (Chain/Storage/DA/Compute modules) for the Flask oracle.

Structural facts:
- **Every `execute.ts` is the same template** (banner box-drawing, shannonEntropy(), makeVector(), ingestToFaiss(), 5× NUM_TXS loop, `/tmp/<chain>_execution_results.json`). The "behavior" extracted is: the executor's *own* 5 self-transfers — self-dealing dust transfers with fabricated φ.
- **φ (the "behavioral truth" score) is a linear ramp of the loop index** in all executors: sui `phi=(i+1)*0.2+0.01`, starknet `0.20+i*0.08` (real) / `0.05+i*0.04` (proof), pvm `(i+1)*0.07+0.2`, ton `(i+1)*0.02+0.003`, near `(i+1)*0.08+0.12`, svm `(txCount+lamports/1e6)/10`. None measure actual entity behavior.
- **Vectors are largely synthetic**: dims 4..127 are `Math.abs(Math.sin(blockNum*(i+1)))*0.1` in every JS executor; botchain builds its vector from hash bytes; only `svm_indexer.py` computes genuine on-chain entropy features (f1–f9).
- **Chain IDs in the JS/Python layer collide and disagree with the Rust indexer layer** (see inventory): SVM JS=900 & PVM JS=900 (collision); Sui JS=101 & svm_indexer.py=101 (collision); StarkNet JS=1300 vs Rust 24000; Sui 101 vs Rust 20100; NEAR 1200 vs Rust 23000; PVM 900 vs Rust 25000. Vectors pushed by executors and indexers for the *same chain* land under *different* chain_ids.
- **`package.json` scripts reference files that do not exist** in 5 of 8 packages (`indexer.ts`, `client.ts`, `program/`, `verify`, `bridge`).
- **Network targeting is inconsistent**: StarkNet mixes SN_MAIN (config/provider) with Sepolia (execute/cairo/package.json); 0G mixes Galileo testnet with mainnet defaults; deployers target testnets (TON, NEAR) while executors target mainnets.
- Only `svm_indexer.py` (block entropies) and `chains/shared/canonical_bh.ts` (byte-exact port of the Rust canonical BH) are high-quality data code.

## Per-chain findings

### chains/ root

- **`chains/shared/canonical_bh.ts`** (140 L, TS) — Canonical Behavioral Hash port "matching rust-indexers/crates/trion-common/src/hash_dna.rs". 93-byte payload: entity_id[32] || event_type[1] || magnitude_nano u64 || context u64 || timestamp u64 || chain_id u32 || block_hash[32]; sense=SHA3-256(payload‖0x00), antisense=sha3ff XOR NOT(sense). `EventType` enum 0–19 (20 types) with a comment requiring match with `behavioral_hash.py` and Rust `event_type_name`. `entityIdFromAddr()` = SHA3-256(normalised address) — this is the only *canonical* BEO derivation in the JS layer. **Not imported by any executor** — none of the per-chain `execute.ts` files use it (they invent their own entity ids). Quality: high; dead code in practice.

## Code quality assessment

- **High quality:** `chains/shared/canonical_bh.ts` (byte-exact spec, cross-language intent), `chains/svm/svm_indexer.py` (real features, rate-limit/back-off/circuit-breaker discipline), StarkNet `src/cairo/btcp_*.cairo` and `src/lib.cairo` (idiomatic Cairo 2.x, events, range asserts, honest comments about fixed bugs), NEAR `contract/src/lib.rs` (clean near-sdk), PVM `contracts/btcp_route` & `genesis` (value-carrying, CEI), TON `execute.ts`/`near/execute.ts` hand-rolled Borsh (educationally correct).

Its executors synthesize the very behavioral scores the protocol claims to measure. trion-0g is a thin but partly real 0G testnet SDK whose DA module is simulated. The headline claims (byte-for-byte BEO across 6 VMs, 96 mainnet chains, 22 VM families, working zero-bridge) are not supported by this code.

**Suggested next actions:** (1) reconcile JS/Python chain IDs with the Rust registry (900-collision, 101-collision, 1300/1200/1100 mismatches); (2) delete or merge the duplicate StarkNet Cairo suites and the minimal `contracts/` legacy generation; (3) rewrite TON FunC storage packing (≤1023-bit cells, slice-vs-ref consistency, int vs slice keys) and fix send_ton value placement before any deploy; (4) make executors use `chains/shared/canonical_bh.ts` (or delete the dead module) and derive φ from real signal features; (5) gate BIRP submit_proof on an actual oracle signature; (6) pick one network (mainnet vs testnet) per package and fix package.json scripts.
