## Overview

These five directories form the **L0 data-ingestion and publishing edge** of the TRION "behavioral truth oracle":

| Component | Language | Files | Role |
|---|---|---|---|
| `indexers/` | Rust 2021 (workspace, 22 crates) | 54 | Poll 21 VM families / ~80 chains via public RPC → compute canonical 93-byte dual-strand Behavioral Hash (BH) + 128-dim entropy vectors → POST to Python FAISS service (`/index/add_batch`, `/index/add_tx_bh_batch`) |
| `validator/` | Go 1.21 (stdlib only, zero deps) | 11 | DW-BFT (Diversity-Weighted BFT) consensus node, P2P gossip mesh, ANIMA crawler coordinator, API gateway, health monitor, clean-room SHA3-256 |
| `signal-processing/` | C++17 | 5 | Radix-2 Cooley-Tukey FFT engine, PSD entropy, wash-trade periodicity detector, sensor interface (BRT/HSM/eco channels) |
| `relayer/` | Node.js ESM (ethers v6) | 4 (lock characterized) | Poll Flask Oracle → pack signal → EIP-191-signed `publishSignal` to ~56 EVM chains + 0G ExecutionGate; non-EVM relayer spawns per-VM `chains/<vm>/execute.ts` + 37 extended chains in synthetic block-proof mode; KMS abstraction (env/AWS/GCP/YubiHSM/PKCS#11) |
| `supervisors/` | Bash | 7 | Process supervisors: restart-on-crash loops for indexers, relayers, oracle server, 0G services |

**Data flow**: chain RPC → Rust indexer (entropy features f1–f9 → `build_vector` 128-dim; per-tx `canonical_bh`) → FAISS/Oracle (Python, port 8000/5000) → relayer.js → `TRIONOracleV3.publishSignal` / `TRIONExecutionGate` on-chain; Go validator mesh + C++ FFT engine sit alongside as independent verification layers.

- `src/hash_dna.rs` (449 L) — **the canonical BH construction**. `canonical_bh(entity_id_hex, event_type u8, magnitude_norm f64, context u64, ts u64, chain_id u64, block_hash_hex) -> (sense_hex, antisense_hex)`:
  - 93-byte payload: entity_id(32) || event_type(1) || magnitude_nano(8, `mag*1e9` as u64 BE) || context(8) || timestamp(8) || **chain_id truncated to u32 BE (4 bytes)** || block_hash(32).
  - sense = SHA3-256(payload‖0x00); antisense = SHA3-256(payload‖0xFF) XOR NOT(sense); invariant sense⊕antisense == NOT(SHA3-256(p‖0xFF)).
  - `classify_event_type(selector)` — EVM 4-byte selector → whitepaper EventType 0–19 (~60 known selectors: Uniswap/1inch/0x/AAVE/Compound/Lido/Maker/Chainlink/LayerZero…). Default → 0 TRANSFER (documented as deliberate). DEPLOY (11) & MEV_CAPTURE (16) handled by callers.
  - `bh_id(addr)` = SHA3-256(normalised address) — entity routing key; `block_entity_id("chain", n)` = `"chain:n"`.
  - **Tests include cross-language golden vectors** (sense `a6639d2a…`, bh_id `f9769049…` claimed to match Python `scripts/cross_lang_bh_check.py` + TS `chains/shared/canonical_bh.ts`) and an antisense-invariant test. Highest-quality file in the repo.
  - Note: `chain_id as u32` truncation is harmless for current IDs (all < 2³², max = Harmony 1666600000 < 4.29e9) but Aurora 1313161554 and Harmony 1666600000 are within u32; Neon 245022934 fine. No overflow *today*.
- `src/faiss.rs` (189 L) — `FaissClient` (20 s timeout) with `add_batch` (block-level `BatchPayload{vectors[1], block_features[9], block_phi, …}`), `add_tx_bh_batch` (`TxBhBatch` per block: `Vec<TxBhEntry>` with tx_hash/from/to/event_type/entity_id/magnitude_norm/value_wei/selector/sense/antisense), `is_healthy()`. - `src/vector.rs` (102 L) — `build_vector([f64;9], seed) -> Vec<f32>(128)`: [0..9]=features, [9..18]=1−f (complementary strand), [18..27]=fᵢ·fᵢ₊₁ (+wrap), [27..31]=mean/std/min/max, [31..63]=SHA3-256(seed) bytes/255 blended 0.7·byte+0.3·mean, [64..128]=0 reserved. `phi_score` = mean of 9. ## Consensus/publishing architecture

1. **Indexing (L0)**: each Rust indexer tails chain heads, computes 9 entropy features per block → 128-dim vector (`build_vector`) + per-transaction canonical BH (`canonical_bh`, 93-byte payload, dual-strand SHA3). Both POST to the Python FAISS service (8000). EVM + Cosmos + UTXO crates index multiple chains per process; others are single-chain.
2. **Oracle (Python, out of scope here)**: computes coherence C(t) vs threshold θ(t); exposes `/api/v1/signal/{entity}` and `/api/v1/self` (SILENCED when self-coherence < threshold).
3. **Publishing (relayer.js)**: every 30–60 s → `checkSelfHalt()` (**fail-closed**: SILENCED or unreachable → publish nothing) → for each entity × each chain with a known oracle address: pack signal (200-bit layout), rebuild the contract's expected digest `keccak256(abi.encodePacked(chainId, oracle, txId, packed))`, EIP-191-sign, submit `publishSignal(txId, packed, [sig])` with retry-on-transient-only. Additionally the 0G ExecutionGate push (richer payload incl. beoHash/daProofHash/storageRoot) on 0G mainnet.
4. **Quorum**: TRIONOracleV3 requires `quorumRequired` validator signatures; the relayer supplies a single-signature array `[sig]` (single-validator setup). Multi-validator would require SIGNER_KEYS_JSON (mentioned in the header docstring but **not implemented anywhere in relayer.js**).
5. **Consensus layer (Go validator, parallel path)**: DW-BFT — diversity weight d_j (mesh: sqrt(consensus-overlap); consensus: 1−corr(model outputs, median)), Σ(t) weighted-in-window ratio, dynamic δ(t), HHI tiers with hard freeze >4000, TCP gossip of BehavioralAttestations, quorum ≥ 2/3 weighted. The Go validator is *not wired into the relayer's on-chain path* — it's an independent verification/informational layer (gateway port serves results).
6. **Non-EVM publishing**: native VMs via spawned `chains/<vm>/execute.ts` (needs keys); everything else = synthetic block-proof ingest into FAISS only (explicitly labeled SYNTHETIC, no on-chain publish).
7. **Supervision**: bash restart-loops per process group; FAISS health-gate before starting indexers; state files under /tmp.

## Code quality assessment

**Strengths**
- `trion-common/hash_dna.rs` is genuinely good: precise byte-layout spec, dual-strand invariant, cross-language golden vectors, honest documentation of classification gaps (DEPLOY/MEV/AIRDROP).
- Uniform indexer template makes 21 crates auditable; RPC failover rotation everywhere; FAISS health-gating everywhere; graceful `continue` on block errors.
- Go validator is stdlib-only with a correct clean-room SHA3-256 and a serious 821-line test suite; DW-BFT math (Σ, d_j, δ(t), HHI) is coherently implemented and matches whitepaper notation.
- Relayer fail-closed self-halt (both relayers), retryable-vs-permanent error discrimination, persistent state with DEGRADED/REJECTED semantics, honest SYNTHETIC provenance labeling in the non-EVM path (a real audit remediation, REL-1/REL-2).
- C++ FFT is textbook-correct with a round-trip test and a real stdin bridge used by the Python pipeline.

**Weaknesses**
- Heavy copy-paste duplication: trion-botchain ≈ trion-evm clone; cmd/validator_mesh.go ≈ internal/p2p/mesh.go (older, non-canonical); crawler exists twice (cmd stub + internal real).
- Dead code: `ChainIndexer` trait never implemented; `living_security.rs` never consumed; `CrawlerSelfTest` never called; signal_conditioning lib unused; `living_security`'s PQCScore is booleans-not-crypto (admitted).
- Data quality varies wildly by chain: EVM/SVM/XRPL/Cardano/Cosmos/Algorand index real per-tx semantics; Sui (digest pseudo-features), UTXO (half-placeholder features, 1 block/poll), StarkNet (2 of 9 features always 0), Pi (ops only for 10 txs) are substantially weaker — the "every chain produces behavioral truth" claim is uneven.
- State in /tmp (ephemeral) across all indexers and relayers.
- Some placeholder/stub surfaces: sensor ecological feed hardcoded; evm_extras supervisor does nothing but health-check.
